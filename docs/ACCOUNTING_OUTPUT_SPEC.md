# MONOLITH — эталон управленческой отчётности из XLSX

**Статус:** спецификация-кандидат, требует подтверждения финансовой методики.  
**Источник:** предоставленная пользователем книга «Управленческий учет 2025 (2)(1).xlsx»; файл и персональные/финансовые данные **не** добавляются в GitHub.  
**Цель:** на выходе MONOLITH должен формировать **содержательный аналог** этой книги: сопоставимую структуру аналитики, планы/факты, расшифровки и сверяемые показатели. Точные стили, расположение ячеек и формат исходных файлов — отдельно согласуемые детали.  
**Связанные правила:** [../AGENTS.md](../AGENTS.md).

## 1. Что есть в книге: карта 17 листов

| Лист | Роль в целевой системе | Особые ограничения |
| --- | --- | --- |
| `ФИНРЕЗ` (скрыт) | Устаревшая месячная сводка с планом, фактом и отклонением | **Не копировать**: 53 формулы `#REF!`, сохранённые ошибки |
| `Сделки (3)` (скрыт) | Предыдущая версия полной сделочной калькуляции | Только для понимания происхождения методики; присутствуют внешние ссылки |
| `Сделки (с выручкой 1С)` | Альтернативная калькуляция с фактом из 1С | Отдельно утвердить приоритет источника выручки |
| `Финрез по сделкам` | Итог на уровне сделки: выручка, себестоимость, маржа и блоки | Денежные показатели по указанному периоду |
| `Финрез.` | Финансовый результат за месяцы, кварталы и год | Агрегировать периоды по правилам ниже |
| `Сделки` | Основной детальный реестр: план, факт, вес и компоненты по блокам | Есть сохранённые ошибки `#DIV/0!` |
| `Производство МК` | Производство: цена ₽/кг, вес, выручка, себестоимость, маржа | Разделить завод / сторонних; кг vs т |
| `Завод` | Выпуск, металл, затраты завода и себестоимость | Проверить НДС и связь по шифру |
| `Сторонние` | Производственные подрядчики: вес, затраты и прибыль | Исключать двойной учёт завода и подрядчика |
| `Документация` | Пооперационный бюджет/факт проектирования | Статья, разработчик, сумма с НДС |
| `Комплектация` | Поставщики, счета, бюджет, факт, частичные переразмещения | Отдельно учитывать частичные перемещения |
| `Доставка` | Логистика: бюджет, факт и экономия | Явные суммы с НДС |
| `кэф` | Исторические коэффициенты производственных затрат | Версионирование и дата действия коэффициента |
| `Финрез по заказчикам` | Сводка по клиентам | Единый справочник контрагентов, не только текстовые имена |
| `Портфель 2026` | План сделок, рентабельность и наценка, виды производства/продажи | Много сохранённых ошибок формул: не использовать как truth data |
| `Текущие` | Операционный статус заказов и сроки исполнения | Не смешивать комментарии по заказу и финансовые суммы |
| `Лист1` | Пустой | Не нужен в целевом отчёте |

## 2. Минимально обязательные отчётные представления

1. **Финансовая сводка:** план/факт/отклонение по выручке, себестоимости и прибыли, рентабельность, месяцы, кварталы, год, накопительный итог. Фильтры: период и подтверждённость.
2. **Реестр сделок:** период, шифр, заказчик, изделие, CRM-ссылка (если доступна), выручка план/факт, себестоимость план/факт, маржа план/факт, дельты, вес план/факт, цена ₽/кг.
3. **Финансовые блоки сделки:** МК, документация, комплектация, доставка, СМР — план, факт и экономия/отклонение; отдельно БГ, штрафы и переразмещения.
4. **Расшифровка МК:** собственное производство и сторонние отдельно, вес, металл, затраты без сырья, цена ₽/кг, себестоимость и прибыль.
5. **Срезы:** финансовый результат по сделкам и по заказчикам, с сохранением одних и тех же итогов.
6. **Портфель и текущие:** плановые показатели и операционные статусы с отличными от факта обозначениями.

**Важно:** это целевое состояние продукта, а не утверждение, что перечисленные представления уже реализованы.

## 3. Наблюдаемые формулы книги (кандидаты на утверждение)

Примеры адресов относятся к листу `Сделки`, строка 7; это **доказательства существующей модели**, а не автоматическое разрешение внедрить её без проверки:

- План выручки: `F7 = V7 + AQ7 + AT7 + AW7 + AZ7` (МК + документация + комплектация + доставка + СМР).
- Факт выручки: `G7 = W7 + AQ7 + AT7 + AW7 + AZ7` (остальные блоки в данном примере остаются плановыми — **критически важно согласовать**).
- План себестоимости: `J7 = AA7 + AQ7 + AT7 + AW7 + AZ7` — проверить, являются ли плановые показатели блока затратами или выручкой.
- Факт полной себестоимости: `K7 = AB7 + AR7 + AU7 + AX7 + BC7 + BA7` (МК + документация + комплектация + доставка + БГ/штрафы + СМР).
- План маржи: `N7 = F7 − J7`; факт маржи: `O7 = G7 − K7`.
- На листе `Производство МК`: `I3 = J3 + K3` (выручка завода и сторонних); `L3 = M3 + N3` (себестоимость), `O3 = P3 + Q3` (прибыль).
- В `Комплектация`: `I3 = G3 − H3` (экономия в рублях).
- В итогах `Финрез.`: квартальные значения суммируются из месячных, например `P5 = SUM(C5:E5)`.

Присутствуют столбцы `∆ %` с формулами **`факт / план`**, например `I7 = G7 / F7`. Это **индекс выполнения**, не процент отклонения `(факт−план)/план`. Нельзя переименовать одно в другое без изменения расчёта и согласования.

## 4. Ключи и источник истины

| Сущность | Ключ | Источник/правило |
| --- | --- | --- |
| Сделка | `deal_code` (шифр), плюс период/версия при необходимости | CRM/B24, ОПП, подтверждённый справочник |
| Контрагент | нормализованный `customer_id` | Сопоставление имён; не string join по произвольному названию |
| Период | `YYYY-MM` | ISO, таймзона и дата закрытия определяются отдельно |
| Блок затрат | `deal_code + period + block + source_version` | МК, документация, комплектация, доставка, СМР |
| Исходный файл | хеш, версия, дата загрузки | Архивировать и сохранять исходные строки/ссылки |
| Расчёт | `calculation_version`, методика, исходные версии | Backend результат; все промежуточные компоненты воспроизводимы |

Не превращать отсутствие строки из источника в ноль через аналог Excel `IFERROR(...,0)` без отдельной бизнес-политики. Не разрешать неоднозначный шифр автоматическим совпадением по первой строке.

## 5. Минимальные проверки, передающие результат в отчёт

- **Структура:** схема, обязательные поля, дата/период, тип суммы/единицы, уникальный шифр, версия файла.
- **Связность:** источник ↔ шифр ↔ заказчик ↔ блок ↔ период; двойная загрузка, отсутствующая или неоднозначная ссылка.
- **Арифметика:** сумма компонентов = итог; факт/план и знак отклонений; маржа/наценка; нулевой знаменатель.
- **Сопоставимость:** цена ₽/кг с весом в кг; НДС; включённость БГ/штрафов; переразмещения.
- **Статусы:** `нет данных`, `черновик`, `конфликт`, `на проверке`, `подтверждён`; изменение источника снимает прежнее подтверждение.
- **Экспорт:** сводка, сделки, детализация и фильтры выводятся из **одного результата расчёта**. Реальные данные не следует заполнять демо-суммами.

## 6. Проверенные проблемы в эталонном XLSX

Структурная проверка XLSX (чтение OOXML без пересчёта книги) выявила:
- `ФИНРЕЗ`: 53 формулы содержат `#REF!`; также обнаружены сохранённые значения ошибок.
- `Сделки`: 21 сохранённая ошибка `#DIV/0!`.
- `Портфель 2026`: 223 `#DIV/0!` и 2 `#REF!` в сохранённых значениях.
- Листы `Сделки (3)`, `Сделки (с выручкой 1С)`, `Сделки` ссылаются на внешний файл по индексам вида `[1]`.

Это **особенности эталона**, а не ошибки кода MONOLITH. Сквозное повторение этих ошибок в новой реализации недопустимо. После открытия книги в Excel число ошибок может отличаться из-за перерасчёта.

## 7. Что надо утвердить до построения полного аналога

1. **Факт выручки:** 1С, сделки, производственный учёт или приоритет/сверка двух источников?
2. **Период отнесения:** дата акта, отгрузки, признания выручки или дата записи?
3. **Себестоимость блоков:** цена продажи, бюджет или затраты; правила распределения общих затрат.
4. **НДС:** единая база, ставки, источники сумм «с НДС» и «без НДС».
5. **БГ/штрафы:** входят ли в полную себестоимость, маржу сделки и отдельную маржу МК?
6. **Проценты:** индекс выполнения или процентное отклонение, рентабельность или наценка, знак экономии.
7. **Порог существенности:** 50 000 ₽ ИЛИ 2% либо И; от какого основания исчислять процент; блокирует ли он утверждение?
8. **Обязательная комплектность:** какие блоки могут оставаться без факта на момент промежуточного отчёта?
9. **Область экспорта:** полная копия всех 17 вкладок или нормализованная структура с теми же показателями.

До решения этих вопросов используем синтетические данные, явные статусы и пометки «демонстрация». Не объявлять шаблон точной копией существующей методики.

## 8. Приёмочные критерии будущей реализации

- Для утверждённой контрольной сделки суммы каждого блока и итог подтверждены бухгалтером; сравнение с Excel **после исправления ошибок эталона**.
- Финрез по сделкам и заказчикам сводится в одинаковый итог за один и тот же период и набор статусов.
- Месячные суммы сводятся в квартал/год; отсутствующий месяц помечается как неполный, не равен нулю.
- Цена ₽/кг и вес кг/т проходят эталонную проверку с документированной точностью.
- Для `план = 0` проценты отображаются как «—»/«не рассчитывается».
- При пропущенном/дублированном шифре не происходит молчаливого объединения или удвоения.
- Отрицательное сторно обрабатывается по утверждённому правилу, не теряется.
- Изменение источника инвалидирует ранее подтверждённый затронутый расчёт.
- Экспортируемая книга открывается в Excel; видимые рассчитанные ячейки не содержат `#REF!`, `#DIV/0!`, `NaN`, `Infinity` и незамеченных внешних ссылок.
- Автотесты, проверка типов, сборка и бухгалтерский контрольный пример задокументированы с **реальными** результатами.

## 9. Границы текущих QA-01…QA-08

Ранее согласованные исправления устраняют дефекты демонстрационного интерфейса, расчётов, экспорта документа, realtime и CI. **Полная загрузка исходных файлов, 1С, ОПП, серверное хранение методик и экспорт полного XLSX — следующий этап**, требующий согласования настоящих источников, бизнес-правил и отдельного объёма разработки.
