# MONOLITH — аудит интерфейса, API и кнопок

**Состояние:** ревью по исходному коду ветки `feature/cashflow-controls-general-parameters`; фактическое браузерное E2E не выполнено. Не путать наличие `onClick` с подтверждением действия в браузере.

## Куда отправляется ИИ-запрос

`src/App.tsx`: кнопка «Анализировать с ИИ» → `runAi()` → `fetch('/api/review-change', {method:'POST', body:{description}})`.

`backend/index.ts`: `router` обрабатывает `POST /api/review-change` → проверка длины 12–5000 символов → `ai.classify()` из `@appdeploy/sdk` с метками `critical_conflict`, `likely_error`, `warning` → JSON-ответ `label,summary,action,rationale`. При исключении возвращает 502. Прямого вызова OpenAI/Gemini/Telegram или API-ключа в коде нет. Реального разговорного чата с историей сообщений тоже нет: это классификация одного текста.

**Локальный Vite:** в `package.json` нет standalone-сервера для `backend/index.ts`. Значит без внешнего серверного контекста POST не работает. Клиент проверяет `GET /api/health` и отключает кнопку, когда API недоступен. Успешный health означает лишь доступность маршрута, а не успешный отклик ИИ.

**Важно для конфиденциальности:** введённый текст при нажатии отправляется в серверное API и далее в ИИ-платформу; не передавайте реальные финансовые данные без отдельно разрешённого режима работы. Открытие карточки/страницы без нажатия «Анализировать» не вызывает ИИ.

| «Проверить с помощью ИИ» из карточки | Предзаполняет описание, открывает раздел проверок; **не отправляет** до нажатия | Реализовано |

## Подтверждённые ограничения
1. Отсутствие рабочего standalone-backend означает, что ИИ на локальном `npm run dev` не отвечает.
2. Нет пользовательского чата с историей, нет собственного API-ключа; используется только `ai.classify` AppDeploy SDK.
3. Список компаний, профиль администратора и старые фальшивые уведомления удалены/переименованы, чтобы не создавать иллюзию авторизации.
4. Удаление реальных данных без серверного хранилища и проверки прав **не добавлено**. Запись внутри JSON невозможно «удалить навсегда» нажатием UI-кнопки без изменения исходников и пересборки.
5. Нет записи в БД, загрузки XLSX через интерфейс, версии источников, журналов решений или настоящего утверждения.
6. Блоки показывают **фактические затраты**, а не распределённую прибыль: бухгалтерская методика не позволяет приписать каждому блоку полную выручку сделки.

## Что проверить в будущем E2E
- Меню, месяцы/год, список без даты, клавиатура в таблице, модальное окно.
- CSV и TXT фактически скачиваются, открываются в Excel/текстовом редакторе.
- `window.print` и закрытие/блокировка нового окна.
- Неудачный `GET /api/health`: ИИ-кнопка отключена, не происходит POST.
- Успешный health и ошибка классификатора: выводится ошибка, а не фиктивный успех.
- Сброс параметров; одновременное изменение видимости блока и фильтра.
- Размеры 320/768/1440 px; консоль, сетевые коды, доступность с клавиатуры.
