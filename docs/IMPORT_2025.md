# Реальный импорт управленческого учёта 2025 — протокол

**Источник:** пользовательский Excel «Управленческий учет 2025 (2)(1).xlsx». **Шифр SHA-256:** `f31eab000f3132223754e5e34d7f0e8aab4e28af42c3b3de44fec01ddb0e86f7`.
**Лист:** `Сделки`; строки 7–97. Исходный XLSX не включён в GitHub: он содержит другие листы, формулы и внешние ссылки.
**Модель статуса:** ВСЕ импортированные сделки `На проверке` до сверки с первичными файлами, 1С и ОПП.

## Состав данных
- 91 строка с уникальными шифрами: 90 относятся к календарным месяцам 2025, одна строка `Сделки!97` не содержит месяца.
- Сохраняем: исходную строку, шифр, период, заказчика, изделие, выручку план/факт, себестоимость план/факт, фактический вес, фактические затраты МК/документации/комплектации/доставки/СМР и БГ/штрафы.
- Не сохраняем: полный исходный файл, внешние Excel-связи, макросы и неподтверждённые формулы. Интеграции 1С, CRM/B24 и синхронизация рабочих источников **не реализованы**.
- `backend/source-2025.ts` — строки источника, доступны только на сервере через `GET /api/deals` после входа. `src/data/management-2025.ts` — типизированный адаптер и логика периодов, без самих данных.
- Исходные денежные ячейки с вычисленным кэшем округлены **до 0,01 ₽ на строку**; точные формулы и неокруглённые кэши остаются в оригинале. Эти JSON нельзя использовать как единственный бухгалтерский первоисточник.

## Результат интерфейса
- Для каждого месяца и года используются фактические строки 2025, а не фиктивные 2026.
- Выручка и полная себестоимость считаются **один раз по сделке**, без удвоения для пяти направлений.
- Расшифровка по блоку показывает фактическую **сумму затрат**, не вымышленную прибыль блока. Пустой источник — «нет данных», ноль — ноль.
- В CSV выводятся период, шифр, заказчик, изделие, план/факт, прибыль, маржа, вес, номер строки и замечание.
- Все результаты предварительные. Отсутствие месяца или разбивки нельзя трактовать как подтверждённый ноль.

## ПРЕДУПРЕЖДЕНИЕ: реальные коммерческие данные
JSON включает реальные названия заказчиков и суммы. **Запрещено развёртывать сборку на публичном сайте без настоящей авторизации**: данные в `src/data` попадают в клиентский JavaScript и доступны всем, кто открывает сайт. Для промышленного внедрения перенести данные в серверную базу, ввести проверку прав на каждую запись и безопасный импорт с версионированием. Никаких реальных секретов/токенов не добавлено.

## Следующие шаги до бухгалтерского утверждения
1. Назначить корректный месяц строке 97.
2. Сверить расхождения строк 34, 51, 52 (в особенности определение фактической выручки).
3. Исправить нулевой вес и формулы цены за килограмм в строках 50, 80, 90, 91, 96.
4. Согласовать НДС, плановые/фактические блоки, правомерность БГ и исключение двойного учёта.
5. Для полного аналога Excel отдельно подключить листы «Завод», «Сторонние», «Документация», «Комплектация», «Доставка», «Финрез.», «Портфель 2026» и др.; это не сделано данным импортом.
