# MONOLITH — управленческий учёт

React + Vite + TypeScript, финансовая сводка и реестр сделок.

**Текущий источник:** предоставленная пользователем книга `Управленческий учет 2025 (2)(1).xlsx`, лист `Сделки`. Исходник в GitHub не копируется. В `backend/source-2025.ts` (только сервер) находится **91 реальная запись**, из них 90 с периодом 2025, одна без периода. Данные предварительные — **не подтверждены** бухгалтером по первичным документам.

## Запуск и проверки

```sh
npm install
npm run dev
npm run typecheck
npm test
npm run build
```

Тестовый контур GitHub Actions запускает `typecheck`, `test` и `build` для `main` и `feature/**` (изменение CI пока находится только в экспериментальной ветке).

## Что реально работает в интерфейсе

- Дашборд за 2025 год/выбранный месяц, динамика только при наличии данных предыдущего месяца.
- Список сделок с поиском, фильтром направления затрат, карточкой, источником и номером строки.
- Корректное разделение полного финансового итога сделки и справочной детализации фактических затрат.
- Экспорт CSV с планом/фактом и статусом, печать/PDF средствами браузера, скачивание положения как TXT.
- Детерминированные проверки, которые не выдают импортированные данные за подтверждённые.
- Панель ИИ, явно показывающая недоступность backend и не отправляющая запросы при отсутствии `/api/health`.

## AI — маршрут запроса

Веб-интерфейс обращается к `POST /api/review-change` на своём домене. Обработчик в `backend/index.ts` передаёт текст через `ai.classify` пакета `@appdeploy/sdk`. **Собственного токена или прямого API OpenAI/Gemini в репозитории нет.** При запуске только через Vite backend отсутствует и ИИ-кнопка отключена. Подробнее: [docs/INTERACTION_AUDIT.md](docs/INTERACTION_AUDIT.md).

## Загрузка файлов и сводный реестр

Раздел «Загрузка файлов» принимает сразу несколько `.xlsx`. Тип определяется автоматически:

| Файл | Как распознаётся | Что даёт |
|---|---|---|
| «Закрытые сделки <Подразделение> <месяц> [год]» | по имени файла | блок подразделения по сделкам: выручка, себестоимость, прибыль план/факт |
| «Номера заказов» | колонка «Шифр для бухгалтерии (ОПП)» | Б24 → шифр бака → шифр ОПП |
| «Расценки» | «К/ты по мес», «стоимость кг» | коэффициент СЗ по месяцам, расценки подрядчиков за кг |
| Отчёт по выпуску СЗ по месяцам | заголовок отчёта | выпуск и списание металла собственного производства |
| Отчёт по выпуску сторонних цехов | заголовок отчёта | выпуск и списание металла у подрядчиков |

**Производство МК** = списание металла + выпуск (т × 1000) × коэффициент. Для СЗ берётся коэффициент месяца, для подрядчика — его расценка за кг (одна на все месяцы). Строки «Склад готовой продукции» работу не начисляют. Выпуск без коэффициента или расценки помечается блокирующим замечанием и в работу не попадает.

**ИИ** (AppDeploy `ai.extract` / `ai.generate`, всё за входом):
- подбирает колонки, если формат файла подразделения не распознан правилами (результат проверяется по границам листа и показывается в предпросмотре до сохранения);
- предлагает сопоставления «сделка без номера → Б24» и «цех → подрядчик из расценок»; применяются только подтверждённые пользователем;
- ищет аномалии в сводке после обязательных проверок системы;
- отвечает на вопросы по сводке сделок.

Числа всегда считает код, а не ИИ.

## Доступ к данным

Финансовые строки 2025 года лежат только на сервере (`backend/source-2025.ts`) и в клиентскую сборку не попадают. Их выдаёт `GET /api/deals` пользователю, который вошёл через AppDeploy и чей адрес почты есть в секрете приложения **`ALLOWED_EMAILS`** (адреса через запятую или с новой строки). Пока секрет не задан, данные не получает никто. Проверка ИИ `POST /api/review-change` закрыта так же.

Ограничения, которые остаются:

- **Репозиторий на GitHub публичный, а данные есть в его истории.** Удаление из кода не убирает их из старых коммитов. Сделайте репозиторий приватным.
- Роли (администратор, руководитель, сотрудник) пока не разделены: все из списка доступа видят все сделки.
- Нет постоянной БД, записи и удаления строк, загрузки XLSX через интерфейс.
